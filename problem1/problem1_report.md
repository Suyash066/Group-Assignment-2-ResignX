# Problem 1 – Smart Home Energy Consumption using a Bayesian Network
Abbreviations: W = Weather, D = DayType, O = Occupancy, A = AC usage, L = Appliance Load, E = Energy.

## Part A – Expert Bayesian Network

**Structure.** W → A, D → O, O → A, O → L, A → E, L → E (diagram: `outputs/network.png`). The network is built from the given CPTs; the code enumerates every parent configuration of every node and checks that each distribution sums to 1. Result: **CPT validation PASS**.

**Inference results (exact inference by enumerating the joint distribution).**

| Query | Probability |
|---|---|
| Q1: P(E=High) | 0.580631 |
| Q2: P(E=High \| W=Hot) | 0.706266 |
| Q3: P(E=High \| D=Weekend) | 0.640199 |
| Q4: P(E=High \| W=Cold, O=High) | 0.484250 |
| Q5: P(W=Hot \| E=High) | 0.608188 |
| Q6: P(A=On \| E=High) | 0.692867 |
| Q7: P(A=On \| E=High, L=Heavy) | 0.649899 |

**Q6 vs Q7 – explaining away.** Both AC usage and heavy appliance load are causes of high energy consumption (A → E ← L). Observing E=High makes AC=On likely: P(A=On | E=High) = 0.6929. If we additionally observe that the load is Heavy, then heavy load is already a sufficient explanation of the high consumption, so the AC is less needed to explain it and the probability falls to P(A=On | E=High, L=Heavy) = 0.6499 (a change of −0.0430). Learning about one cause lowers belief in the other cause once their common effect is known; this is the explaining-away effect.

**Q1 by hand.** Condition on Occupancy (the common ancestor of A and L) and sum over A and L:

P(E=High) = Σ_O P(O) Σ_A P(A | O) Σ_L P(L | O) P(E=High | A, L)

1. Occupancy: P(O=High) = 0.7·0.45 + 0.3·0.80 = 0.555, so P(O=Low) = 0.445.
2. AC given occupancy (sum over Weather, with P(W) = 0.5, 0.3, 0.2):
   - P(A=On | O=High) = 0.5·0.90 + 0.3·0.40 + 0.2·0.10 = 0.59
   - P(A=On | O=Low) = 0.5·0.60 + 0.3·0.15 + 0.2·0.05 = 0.355
3. Energy given AC and occupancy (sum over Load):
   - O=High, P(Heavy) = 0.75: P(E=High | A=On) = 0.75·0.92 + 0.25·0.68 = 0.86; P(E=High | A=Off) = 0.75·0.55 + 0.25·0.12 = 0.4425
   - O=Low, P(Heavy) = 0.35: P(E=High | A=On) = 0.35·0.92 + 0.65·0.68 = 0.764; P(E=High | A=Off) = 0.35·0.55 + 0.65·0.12 = 0.2705
4. Sum over AC:
   - O=High: 0.59·0.86 + 0.41·0.4425 = 0.68883
   - O=Low: 0.355·0.764 + 0.645·0.2705 = 0.44569
5. P(E=High) = 0.555·0.68883 + 0.445·0.44569 = 0.38230 + 0.19833 = **0.580631**

The code gives 0.580631, so the hand calculation matches (`Match: True` in `part-a.png`).

## Part B – Conditional Independence (d-separation)

| Statement | d-separation | Numerical check |
|---|---|---|
| 1. W ⊥ D | **Holds** | P(W=Hot) = 0.500000; P(W=Hot \| D=Weekend) = 0.500000 (diff 2.2e-16) |
| 2. W ⊥ D \| E | **Does not hold** | P(W=Hot \| E=High) = 0.608188; P(W=Hot \| E=High, D=Weekend) = 0.599751 (diff 8.4e-03) |
| 3. W ⊥ L \| O | **Holds** | P(W=Hot \| O=High) = 0.500000; P(W=Hot \| O=High, L=Heavy) = 0.500000 (diff 1.1e-16) |

**Justification.**
1. The only path between W and D is W → A ← O ← D. A is a collider and neither A nor its descendant E is observed, so the path is blocked. W and D are independent.
2. Conditioning on E (a descendant of the collider A) activates the collider, so the path W → A ← O ← D becomes open. W and D become dependent. Intuitively, if the energy is high and it is a weekend (so occupancy is probably high, which explains high AC use), a hot day is slightly less necessary to explain the observation, so P(W=Hot) changes.
3. The paths between W and L are W → A ← O → L. A is an unobserved collider, so this path is blocked even before conditioning; conditioning on O (a fork node on this path) keeps it blocked. No other path exists. W and L are independent given O.

The numbers agree with the d-separation answers: the conditional probabilities are identical in 1 and 3 and different in 2.

## Part D – Learning from Data

Same structure as the expert network. Two estimators per dataset:
- **MLE:** conditional relative frequencies from counts.
- **Bayesian estimation (BDeu, equivalent sample size 10):** pseudo-count of 10/(r·q) added to each cell (r = states of the node, q = parent configurations).

All learned CPTs were validated (every distribution sums to 1: PASS for MLE and BDeu at all three sizes).

Between 5000 and 20000 it stays at about 0.002 and does not decrease further, because the remaining error is sampling noise of one particular random draw rather than estimation bias (a single seed, so the curve is not guaranteed to be monotonic).

### 2. Largest error at N=500

**Q4 = P(E=High | W=Cold, O=High)** has the largest error for both estimators (MLE 0.0639, Bayesian 0.0575). Its evidence, Cold weather together with High occupancy, occurs in only **51 of 500 rows** (the true probability of this combination is 0.2·0.555 ≈ 11%). Within those rows, AC=On occurs only **5 times** and Energy=High 21 times, so the CPT entries Q4 relies on (P(A | Cold, High) and P(E | A, L) in the sparse AC=On cases) are estimated from a handful of examples and are very noisy. Queries whose evidence is common (Q1, Q3) or only needs well-populated parent configurations are estimated far more reliably.

### 3. Which estimator is better for small datasets

For the small dataset (N=500) Bayesian estimation with the BDeu prior has the slightly lower mean error (0.0272 vs 0.0287), and it is lower on Q4, Q5, Q6 and Q7, although MLE is better on Q1, Q2 and Q3, so the advantage is modest. The reason is that the prior adds a small number of virtual observations to every cell, which pulls sparse estimates away from extreme values (for example, Cold/Low AC: MLE 0.0196 vs BDeu 0.0348 against a true 0.05). This trades a little bias for lower variance, and it also guarantees that no probability becomes exactly 0 or 1 or undefined when a parent configuration is rare or never observed, which would make some evidence impossible under the model. With 5000 or more samples every parent configuration has hundreds of observations, the pseudo-counts become negligible, and the two estimators give nearly identical results (the small differences in the table, in either direction, are noise). So the benefit of Bayesian estimation is largest for small datasets and disappears as the amount of data grows; with a single seed, the gap at N=500 is small and should not be over-interpreted.
